# 업다운 멜로디 — 단계별 바이브코딩 프롬프트 설계서

버전 1.0 · 2026-11-11 · 짝이 되는 문서: 업다운멜로디_기획서.md (저장소 안에서는 `docs/spec.md`)

## 이 문서를 쓰는 법

- 단계는 순서대로 하나씩 합니다. 단계마다 목표, 붙여 넣을 프롬프트, 확인 방법, 막혔을 때가 있습니다.
- 프롬프트는 회색 상자 안을 통째로 복사해 AI 코딩 도구(Claude Code 등)에 붙여 넣습니다.
- '확인 방법'을 통과한 뒤에 다음 단계로 갑니다. 통과하지 못하면 '막혔을 때'의 프롬프트를 씁니다.
- 대화가 길어져 새 대화를 열었다면 맨 아래 '자주 쓰는 프롬프트'의 **이어가기**를 먼저 붙여 넣습니다.
- 규칙과 수치는 이 문서가 아니라 기획서가 기준입니다. 프롬프트에는 기획서의 장 번호만 적었습니다.

## 준비

1. 컴퓨터에 Node.js(LTS 버전), Git, AI 코딩 도구가 설치되어 있어야 합니다. 배포에는 GitHub 계정과 Vercel 계정이 필요합니다.
2. 작업할 폴더를 만듭니다. 이름은 `updown-melody`로 합니다.
3. 그 안에 `docs` 폴더를 만들고 받은 파일 4개를 넣습니다.
   - `업다운멜로디_기획서.md`
   - `업다운멜로디_프롬프트설계서.md` (이 문서)
   - `updown_golden_v1.json` (규칙 검증 자료)
   - `engine.reference.ts` (규칙 엔진 참조 구현)
4. AI 코딩 도구를 `updown-melody` 폴더에서 엽니다.

## 단계 1. 작업 규칙 세우기와 파일 정리

목표: AI가 기획서를 기준으로 삼고, 한 단계씩만 진행하고, 검증 자료를 건드리지 않게 약속을 정합니다.

```
이 폴더에서 「업다운 멜로디」라는 모바일 웹 카드게임을 만들 거야. 나는 개발자가 아니고, 너와 대화하면서 한 단계씩 만든다.

먼저 다음을 해 줘.
1. docs 폴더의 파일 이름을 바꿔 줘. 한글 파일명은 맥과 윈도우 사이에서 깨질 수 있어서야.
   - 업다운멜로디_기획서.md → docs/spec.md
   - 업다운멜로디_프롬프트설계서.md → docs/prompts.md
   - updown_golden_v1.json 과 engine.reference.ts 는 그대로 둔다.
2. docs/spec.md 를 처음부터 끝까지 읽어 줘. docs/updown_golden_v1.json 은 약 580KB라서 열어 읽지 마. 구조는 spec.md 부록 B에 있다.
3. 네가 매번 읽는 프로젝트 지침 파일(Claude Code면 CLAUDE.md, 다른 도구면 AGENTS.md)에 아래 [작업 규칙]을 그대로 넣어 줘. 파일이 이미 있으면 지우지 말고 덧붙여 줘.
4. git 저장소를 만들고 첫 커밋을 해 줘.
5. 끝나면 spec.md 의 내용을 다섯 줄로 요약하고, 모순돼 보이거나 이해가 안 되는 부분이 있으면 알려 줘. 아직 코드는 만들지 마.

[작업 규칙]
- 기준 문서는 docs/spec.md 다. 구현이 문서와 다르면 문서가 맞다. 문서에 없는 규칙을 만들거나 바꾸지 않는다. 문서가 모호하거나 틀려 보이면 멈추고 나에게 묻는다.
- 한 번에 한 단계만 한다. 단계는 docs/prompts.md 의 순서를 따른다. 내가 다음 단계를 시키기 전에는 넘어가지 않는다.
- 규칙 엔진의 정답은 docs/engine.reference.ts 와 docs/updown_golden_v1.json 이다. 시험이 실패하면 엔진을 고친다. 검증 자료, 기대값, spec.md 의 기준 수치는 고치지 않는다.
- docs/updown_golden_v1.json 은 통째로 읽지 않는다. 시험 코드에서 불러 쓴다.
- src/game 폴더의 코드는 화면이나 브라우저 기능을 쓰지 않는다. 화면 쪽에서는 규칙을 다시 계산하지 않고 엔진의 판정 결과만 쓴다.
- 새 라이브러리가 필요하면 이유를 말하고 내 허락을 받은 뒤 설치한다.
- 단계를 마치면 시험, 형식 검사, 타입 검사를 돌려 통과시킨 뒤 "단계 N 완료: 요약"이라는 메시지로 커밋한다.
- 보고는 쉬운 한국어로 한다. 단계가 끝날 때마다 ① 무엇을 만들었는지 ② 내가 직접 확인하는 방법(주소, 누를 버튼, 보여야 할 화면) ③ 확인하지 못했거나 남은 문제를 구분해서 알려 준다. 긴 로그는 붙이지 않는다.
- 화면 문구는 한국어로, 초등학생이 읽을 수 있는 짧은 존댓말로 쓴다. 다른 보드게임의 이름은 쓰지 않는다.
```

확인 방법
- `docs` 폴더에 `spec.md`, `prompts.md`, `updown_golden_v1.json`, `engine.reference.ts` 네 파일이 있습니다.
- AI의 요약에 "보정 규칙", "AI 대전", "초급·기본 모드"가 들어 있습니다.
- AI가 모순이나 질문을 내놓으면 다음 단계로 가기 전에 답합니다. 답하기 어려우면 이 설계서를 만든 대화로 가져와 물어보세요.

## 단계 2. 프로젝트 뼈대

목표: 빈 화면이라도 브라우저에 뜨는 프로젝트를 만듭니다.

```
docs/prompts.md 의 단계 2를 진행하자. docs/spec.md 12장을 읽고 프로젝트 뼈대를 만들어 줘.

- Next.js(App Router) + TypeScript(strict) + Tailwind CSS + Zustand + Vitest. 버전은 지금 안정 버전으로.
- 서버 기능 없이 정적 파일만으로 동작하게 설정한다(정적 내보내기).
- 지금 폴더에 만든다. docs 폴더와 그 안의 파일은 그대로 남아야 한다. 프로젝트 생성 도구가 "폴더가 비어 있지 않다"고 하면 임시 폴더에 만든 뒤 옮겨 줘.
- spec.md 12장의 폴더 구조를 만든다. 아직 내용은 비워 둔다.
- 홈 화면에는 제목 "업다운 멜로디"와 "준비 중이에요" 문구만 둔다.
- 명령을 준비한다: 개발 서버, 빌드, 시험, 형식 검사.
- 개발 서버를 띄우고, 내가 브라우저에서 열 주소를 알려 줘.
```

확인 방법
- AI가 알려 준 주소(보통 `http://localhost:3000`)를 브라우저에서 열면 "업다운 멜로디" 제목이 보입니다.
- AI의 보고에 빌드와 시험이 통과했다고 적혀 있습니다.

막혔을 때

```
개발 서버 주소를 열었는데 화면이 안 떠. 터미널에 나온 오류를 읽고 원인을 한 문장으로 설명한 다음 고쳐 줘. 고친 뒤 다시 주소를 알려 줘.
```

## 단계 3. 규칙 엔진 들여오기와 검증

목표: 규칙 엔진을 프로젝트에 넣고, 정답 파일로 전부 맞는지 확인합니다. 이 단계가 통과하면 게임 규칙은 맞게 들어간 것입니다.

```
docs/prompts.md 의 단계 3을 진행하자. docs/spec.md 4장, 5장, 6장, 부록 B를 읽어 줘.

1. docs/engine.reference.ts 를 src/game/ 으로 들여온다. 이 파일은 규칙 엔진의 참조 구현이고 검증 자료를 전부 통과한다. 그대로 써도 되고 파일을 나눠도 되지만 규칙의 뜻은 바꾸지 않는다.
2. 시험을 만든다(src/game/__tests__/).
   - 카드 구성: 기본 모드 92장, 초급 모드 60장, 음높이 카드 삑점 합 90, 색별 숫자 목록이 spec.md 4.1과 같다.
   - 검증 자료 docs/updown_golden_v1.json 의 세 묶음을 모두 확인한다. 비교 방법은 spec.md 부록 B를 따른다.
     · scenarios: illegal 단계는 엔진이 거부하고 상태가 바뀌지 않는지, 나머지는 적용 뒤 상태가 post 와 같은지
     · placement: 손패 카드마다 playable, legalLines, targets, explodes 가 같은지, mustDraw 가 같은지
     · replays: 단계마다 상태가 post 와 같은지, 마지막에 endReason 과 scores 가 같은지
   - 행동의 카드는 index 가 아니라 card 문자열로 손패에서 찾는다.
3. 시험을 돌리고, 묶음마다 몇 개를 확인했고 몇 개가 통과했는지 알려 줘.

검증 자료 파일은 통째로 읽지 말고 시험 코드에서만 불러 써. 시험이 실패하면 검증 자료가 아니라 엔진이나 시험 코드를 고쳐.
```

확인 방법
- AI의 보고에 다음 숫자가 그대로 나와야 합니다: 시나리오 15개(39단계), 배치 판정 374건, 재생 기록 14판(562단계), 실패 0.
- 숫자가 다르면 일부만 확인한 것입니다. 아래 프롬프트를 씁니다.

막혔을 때

```
단계 3의 보고 숫자가 기준과 달라. 기준은 시나리오 15개(39단계), 배치 판정 374건, 재생 기록 14판(562단계), 실패 0이야. 빠뜨린 묶음이나 건너뛴 사례가 없는지 확인하고, 실패가 있으면 첫 번째 실패 하나만 골라서 어떤 규칙(spec.md 5장의 몇 번)과 어긋났는지 설명한 뒤 엔진을 고쳐 줘. 검증 자료와 기대값은 건드리지 마.
```

## 단계 4. 자동 대전 점검 도구

목표: 검증용 AI끼리 수천 판을 돌려, 폭발 횟수 같은 수치가 기준과 맞는지 확인하는 명령을 만듭니다. 나중에 규칙이나 엔진을 손댔을 때도 이 명령 하나로 다시 확인합니다.

```
docs/prompts.md 의 단계 4를 진행하자. docs/spec.md 8.4와 8.5를 읽어 줘.

1. 자동 대전 스크립트를 만든다(scripts/sim.ts). 엔진의 검증용 AI와 simulate 함수를 쓴다.
2. spec.md 8.5의 표에 있는 12개 조건을 각각 5,000라운드씩 돌린다.
3. 8.5의 기준값과 허용 오차를 스크립트 안에 넣고, 조건마다 여섯 지표의 값, 기준값, 차이, 합격 여부를 표로 출력한다. 마지막 줄에 "12개 조건 모두 합격" 또는 벗어난 항목 목록을 쓴다.
4. 명령 하나로 돌릴 수 있게 한다(예: npm run sim). TypeScript 스크립트를 실행할 도구가 필요하면 무엇을 쓸지 말하고 허락을 받아 줘.
5. 실행해서 결과 표를 보여 줘.

기준에서 벗어나는 항목이 있으면 기준 수치를 고치지 말고 원인을 찾아 줘. 지표를 세는 방법이 8.5의 '지표의 뜻'과 같은지 먼저 확인해.
```

확인 방법
- AI가 보여 준 표의 마지막 줄이 "12개 조건 모두 합격"입니다.
- 참고로 기본 모드 4인 A의 폭발은 4.1 안팎, 초급 4인 A는 4.0 안팎이 나와야 합니다.

## 단계 5. AI 3단계

목표: 쉬움·보통·어려움 AI를 만들고, 실제로 실력 차이가 나는지 승률로 확인합니다.

```
docs/prompts.md 의 단계 5를 진행하자. docs/spec.md 8.1, 8.2, 8.3, 8.6을 읽어 줘.

1. src/game/ai.ts 에 게임용 AI를 만든다. 수준은 쉬움, 보통, 어려움. 쉬움은 검증용 AI A와 같다. 초급 모드에서 어려움을 요청하면 보통으로 동작한다.
2. AI는 자기 손패와 공개 정보만 본다. 다른 사람의 손패와 뽑기 더미의 내용을 읽지 않게 만든다.
3. 시험: 수준마다 2,000라운드를 돌려 AI가 규칙에 어긋난 행동을 한 번도 하지 않는지 확인한다.
4. 승률 점검 명령을 만든다(예: npm run sim:ai). 자리 하나에 시험할 AI, 나머지 자리에 보통 AI를 앉혀 4인전 3,000라운드를 돌리고 spec.md 8.6의 합격 기준과 비교해 출력한다.
   - 기본 모드: 쉬움 18% 이하, 어려움 32% 이상
   - 초급 모드: 쉬움 17% 이하
5. 실행해서 결과를 보여 줘.

합격하지 못하면 8.2와 8.3의 규칙을 문장 하나씩 코드와 대조해서 다른 곳을 찾아 줘. 기준을 낮추지는 마.
```

확인 방법
- 세 기준이 모두 합격입니다. 참고값은 기본 4인에서 쉬움 13%, 보통 25%, 어려움 37% 안팎입니다.

## 단계 6. 게임 진행(세션)과 저장

목표: 한 게임(여러 라운드)의 흐름을 관리하는 부분을 만듭니다. 화면은 아직 없습니다.

```
docs/prompts.md 의 단계 6을 진행하자. docs/spec.md 5.2의 6번, 5.9, 5.10, 5.11, 6.4, 11장을 읽어 줘.
```
